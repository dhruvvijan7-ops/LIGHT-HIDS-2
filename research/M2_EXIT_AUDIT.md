## ② Evidence survives the purge (reject-condition R1)

drives three stages against one planted finding:

1. **hot** — `/v1/workspaces/ws-b/evidence/{findingUid}`

   `{finding_uid, evidence_snapshot, raw_state: "hot", raw_object: {sha256, size}}`

2. **purged** — `raw_objects.state` flipped to `purged` with `purged_at`, then

`sentinel_detect.evidence.build_snapshot` (`packages/detect/sentinel_detect/evidence.py:134`):
`schema_version sentinel-evidence/v1`, the finding, the rule

`source_sha256`), `run {run_id, config_hash}` and one entry per contributing
event (`event_uid`, `sha256`). The test recomputes each digest from the
snapshot's own inputs and asserts equality, so "complete snapshot" is checked
structurally, not by presence alone. `test_m2_exit_2_triage_update_keeps_the_snapshot`
(`:289`) adds the R1 corollary: a `PATCH /findings/{id}` triage update must
not rewrite the evidence.

prose at `:417-423` promises an optional presigned link whose fields are

## ④ Cold-start codes in the run summary

Code surface: `_BASELINE_MISSING` / `_BASELINE_WARMUP`
(`packages/detect/sentinel_detect/runner.py:54-55`), decided from
`rule_baseline` observations via `_BASELINE_OBSERVATIONS_SQL`
(`runner.py:48-52`) and `_cold_start_codes` (`runner.py:125-144`), with the
threshold read by `_min_observations` (`runner.py:113-122`). `_prepare`
(`runner.py:95-110`) splits rules into (runnable, suppressed-with-codes), and
`run_detection` (`runner.py:186`) surfaces the codes on the run, which is
completed as `completed_with_warnings` (`runner.py:297`) — never silent
(§4.8).

Three gates:

- `test_m2_exit_4_missing_baseline_is_reported` (`test_m2_exit.py:375`) — a
  statistical rule with no baseline rows is suppressed with `BASELINE_MISSING`
  in both the per-rule run row and the run summary;
- `test_m2_exit_4_warmup_baseline_is_reported` (`:393`) — seeded buckets below
  `min_observations` yield `BASELINE_WARMUP` and not `BASELINE_MISSING`;
- `test_m2_exit_4_a_valid_baseline_lifts_the_suppression` (`:427`) — enough
  observations ⇒ `_prepare` returns the rule as runnable (gate open).

Writing this gate found two real defects, both fixed in `runner.py`:

1. `_BASELINE_OBSERVATIONS_SQL` summed `o.observations` from a `FROM rule_baseline`
   with no alias → `psycopg.errors.UndefinedTable: missing FROM-clause entry for
   table "o"` on the first cold-start check;
2. `_cold_start_codes` read a top-level `document["baseline"]`, which the rule
   schema forbids (`additionalProperties: false`, no `baseline` property), so
   the threshold was always 0; it now reads `statistical.baseline` first
   (`runner.py:113-122`).

Related, not yet executable: `warmup_action: flag` is not implemented
(**M2-A3**) and `kind: statistical` has no window engine at M2 (**M2-A4**).

**Verdict: PASS.**

The dataset is out-of-tree by policy (D6-009: *rule* corpora may be
committed, datasets may not; V-6-035 records UNSW's academic-use /
no-commercial terms), so the exit is gated the same way CI sees it:
**fetch → verify pins → score → assert**.

| Piece | Where |
|---|---|
| Pins (sha256 + bytes + rows) | `tools/evaluate_unsw_nb15.py:PINNED` — train `bec7dd5e…48fa` 175 341 rows / 32 293 018 B; test `734fe664…a559` 82 332 rows / 15 380 800 B |
| Fetch + attribution manifest | `tools/corpus_fetch.py:fetch_unsw_nb15` — hard failure (exit 2) on a missing corpus or sha/size drift; writes `.corpus/unsw-nb15/manifest.json` carrying the MilCIS 2015 citation |
| CSV → canonical mapping | `packages/ingest/sentinel_ingest/unsw_nb15.py` (`read_flows`, `EXPECTED_COLUMNS` header enforcement, `_canonical_value` with the `math.isfinite` guard) + pipeline `unsw_nb15_network_flow` (`configs/sigma_field_mapping_pipelines.yaml:315`, **M2-A10**) |
| Ground truth | `label` / `attack_cat` are carried beside the document as targets only — banned from `detection`, absent from `unmapped[]` (harness fails if either leaks) |
| Pack | `tests/scoring/rules/` — 6 rules frozen 2026-10-12, thresholds tuned on the *training* split |
| Gate | `tests/scoring/test_unsw_nb15_scoring.py` (11 tests), `test_unsw_nb15_pack.py` (13), `test_unsw_nb15_mapping.py` (15); fixtures in `tests/scoring/conftest.py` fail — never skip — when the corpus is absent |
| Evidence | `research/work/_stage6_work/bench/unsw_nb15_scoring.json` (regenerated by every run) |

Measured on the pinned corpus (257 673 rows total, 0 dropped, 0
schema-invalid against `canonical_event_v1.schema.json`):

| split | rows | precision | recall | F1 | FPR (Normal) | min per-category recall |
|---|---|---|---|---|---|---|
| train | 175 341 | 0.9537 | 0.8851 | 0.9181 | 0.0916 | 0.549 (Fuzzers) |
| test | 82 332 | 0.8380 | 0.9394 | 0.8858 | 0.2225 | 0.764 (Fuzzers) |

All nine attack categories are scored on both splits (test recall .764–1.000).
The gate's floors are the numbers above minus the regression margin
(train F1 ≥ .90 / P ≥ .94 / R ≥ .87 / FPR ≤ .10 / min-cat ≥ .50; test
F1 ≥ .86 / P ≥ .82 / R ≥ .92 / FPR ≤ .25 / min-cat ≥ .70), so any rule edit
that costs a category fails CI.

Building this exit found and fixed two engine defects, both covered by
`tests/unit/test_evaluate_numeric_text.py`: `_as_text` rendered floats as
`1e-05` while the SQL path sees jsonb's plain decimal `0.00001` (the shared
`^-?[0-9]+([.][0-9]+)?$` guard then rejected native values, silently falsing
every sub-1e-4 comparison such as `dur|lte: 5` on 2 µs flows), and a
non-finite value (`NaN`) would have serialised to invalid JSON for
PostgreSQL.

**Verdict: PASS.**
